<h1>Trois conteneurs, une seule grammaire

Un conteneur se déclare comme toute variable — le nom, le deux-points, le type en toutes lettres, puis la valeur. Le type est toujours écrit ; le point-virgule sépare les éléments ; l'accolade les rassemble. Les indices commencent à 0, comme en NSI.

<h1>La collection

soit notes: une collection de décimaux = {12,5 ; 15 ; 9,5}
soit mots: une collection de textes = {chat ; chien ; cheval}

Le dièse affiche le conteneur entier : #notes — et l'indice lit un élément : la deuxième note est #notes[1], le premier mot est #mots[0]. Un élément entre dans un calcul comme toute valeur : le double de la deuxième note vaut #{notes[1] * 2}.

L'écriture indexée modifie une case existante, sans soit puisque rien n'est déclaré :

notes[2] = 14

Après correction : #notes. En revanche, lire au-delà des bornes est une erreur, et docdg la dit au lieu de se taire : #notes[7].

<h2>Grandir par concaténation

Une collection déclarée vide grandit par +, qui concatène toujours deux conteneurs — l'élément ajouté s'écrit donc en singleton, entre accolades :

soit S: une collection d'entiers = {}
pour k de 1 à 5 {
	soit S = S + {k * k}
}

Les cinq premiers carrés : #S.

<h1>Le dictionnaire

soit trajets: un dictionnaire de textes et d'entiers = {Marche: 5 ; Bus: 3}

La clé lit sa valeur : à pied, #trajets[Marche] minutes. Le + ajoute une paire :

soit trajets = trajets + {Vélo: 7}

Le dictionnaire complet : #trajets. Une clé absente est une erreur explicite : #trajets[Métro].

La boucle dans livre les clés, et l'indexation retrouve chaque valeur :

pour t dans trajets {
	#t : #{trajets[t]} minutes.
}

<h1>La matrice

Une matrice porte ses dimensions dans son type. La forme littérale tient sur une ligne ; la forme bloc s'aligne à l'œil dans l'éditeur — tabulations entre colonnes, retours à la ligne entre rangées, aucun point-virgule :

soit A: une matrice 2×2 d'entiers = {{1 ; 2} ; {3 ; 4}}
soit B: une matrice 2×2 d'entiers = {
	5	6
	7	8
}

A vaut #A et B vaut #B. Une case se lit par [ligne ; colonne] : #A[0 ; 1] puis #B[1 ; 0].

Déclarée avec {}, une matrice naît remplie de ses valeurs par défaut, puis se remplit case par case :

soit T: une matrice 3×3 d'entiers = {}
pour i de 0 à 2 {
	pour j de 0 à 2 {
		T[i ; j] = (i + 1) * (j + 1)
	}
}

La table de multiplication : #T — et sa case centrale : #T[1 ; 1].

<h1>Composer les conteneurs

Un tableau à plusieurs dimensions dont la taille n'est pas connue d'avance est une collection de collections. La rangée se déclare dans la boucle — elle repart vide à chaque tour — pendant que le conteneur extérieur, déclaré avant, accumule :

soit M: une collection de collections d'entiers = {}
pour i de 0 à 2 {
	soit rangée: une collection d'entiers = {}
	pour j de 0 à 3 {
		soit rangée = rangée + {i * j}
	}
	soit M = M + {rangée}
}

Le résultat : #M.

<h1>Les quatre types de nombres

Le langage distingue les ensembles tels que les mathématiques les enseignent : un entier appartient à \(\mathbb{Z}\), un décimal à \(\mathbb{D}\) — son développement décimal est fini — un réel à \(\mathbb{R}\), et un complexe est un couple de deux réels.

soit ent: une collection d'entiers = {1 ; -4 ; 12}
soit dec: une collection de décimaux = {12,5 ; 0,25 ; 15}
soit ree: une collection de réels = {1/3 ; racine(2) ; 2,5}
soit cpx: une collection de complexes = {(1 ; 2) ; (0 ; -1)}

Entiers : #ent — décimaux : #dec — réels : #ree — complexes : #cpx. Le second complexe vaut #cpx[1], couple dont la partie réelle est nulle.

L'inclusion \(\mathbb{D} \subset \mathbb{R}\) se vérifie dans les deux sens : un tiers est un réel parfaitement légitime, mais son développement décimal est infini, donc il n'est pas décimal — et docdg le dit :

soit faux_decimal: une collection de décimaux = {1/3}

<h1>Le type protège

Le type déclaré est vérifié à chaque instant — et l'erreur parle, avec la ligne fautive, plutôt que de composer un document faux :

soit E: une collection d'entiers = {1 ; 2,5 ; 3}
