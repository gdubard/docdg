<h1>Ce que ce document couvre

Déclarer une variable et l'initialiser, poser une question au lecteur, décider selon une condition, répéter un traitement. Chaque structure s'y montre d'abord seule, puis les deux se mêlent : une condition à l'intérieur d'une boucle décide, tour par tour, ce qui reste dans le document.

<h1>Variables et sortie

Une variable se pose avec `soit`, se relit avec `#`, entre dans un calcul avec `#{...}` — l'équivalent d'une affectation suivie d'un affichage.

soit tva = 0,2
soit prix = 150
Le prix TTC est #{prix * (1 + tva)} euros.

<h1>Une boucle simple

`pour` répète un bloc un nombre de fois connu à l'avance — l'équivalent d'un `for`.

pour k de 1 à 3 {
	Ligne #k : le carré de #k vaut #{k*k}.
}

<h1>Une condition simple

`si ... sinon` choisit entre deux issues, une fois, sans répétition.

soit note = 12
si note au moins 10 {
	Admis avec #note.
}
sinon {
	Ajourné.
}

<h1>Une boucle avec un pas négatif

Le pas se règle en prose, comme tout réglage : `avec un pas de p`. Ici la boucle avance de 0,25 en 0,25.

pour k de 2 à 0 avec un pas de -0,25 {
	Terme #{défaut(-4*k)+9} : #k.
}

<h1>Une boucle qui filtre

<h2>Les multiples de 3 entre 1 et 20

Aucune ligne n'est écrite pour les tours silencieux — ils n'existent simplement pas dans le résultat. Chaque tour retenu forme sa propre ligne : c'est la boucle elle-même qui écrit le document, tour après tour.

pour n de 1 à 20 {
	si n % 3 vaut 0 {
		Multiple retenu : #n
	}
}

<h2>La même idée, en tableau

<Dresse>un tableau [mc ; mc]{
	n	Multiple de 3 ?
	pour n de 1 à 20 {
		si n % 3 vaut 0 {
			[#n ; oui]
		}
	}
}

<h1>Chercher les diviseurs d'un entier

Un entier \(d\) divise \(n\) lorsque le reste de la division de \(n\) par \(d\) est nul. Balayer tous les diviseurs candidats de 1 à \(n\), et ne retenir que ceux qui divisent effectivement, donne la liste complète des diviseurs — la première brique, sur le papier comme ici, de tout test de primalité.

<Dresse>un tableau sécable [mc ; mc]{
	Diviseur	de 84
	pour d de 1 à 84 {
		si 84 % d vaut 0 {
			[#d ; convient]
		}
	}
}

Un nombre premier n'a, par définition, aucun diviseur strictement compris entre 1 et lui-même. La table ci-dessus liste ceux de 84 — huit en tout, largement plus que les deux attendus d'un nombre premier.

<h1>Filtrer par intervalle

`appartient à` et sa négation `n'appartient pas à` filtrent un intervalle aussi simplement qu'un test de divisibilité — utile chaque fois que l'algorithme cherche « à partir de quel rang » une grandeur franchit un seuil.

<Dresse>un tableau [mc ; mc ; mc]{
	Rang	Terme	Écart
	pour n de 0 à 20 {
		si (n appartient à [16;20]) {
			[#n ; #{2^(n+1) - 1} ; #{2^n}]
		}
	}
}

<h1>L'opérateur ternaire

`si ... sinon` peut aussi produire une valeur plutôt que du texte — affecté directement à une variable, comme un opérateur ternaire.

soit n = 17
soit parité = si n % 2 vaut 0 { pair } sinon { impair }
#n est #parité.

<h1>Conditions composées

`et` comme `ou` combinent deux conditions dans le même test ; les parenthèses en précisent l'ordre quand les deux se mêlent.

<Dresse>un tableau [mc ; mc]{
	n	Retenu
	pour n de 1 à 30 {
		si n % 3 vaut 0 et n % 5 vaut 0 {
			[#n ; multiple de 15]
		}
	}
}

soit n = 5
si (n % 3 vaut 0 et n % 5 vaut 0) ou n vaut 5 {
	Retenu par l'exception.
}
sinon {
	Écarté.
}

<h1>L'accumulateur

Une variable posée avant la boucle et réaffectée à l'intérieur garde sa valeur d'un tour au suivant : c'est l'accumulateur, celui qui totalise une somme ou compte les cas retenus.

soit somme = 0
pour k de 1 à 100 {
	soit somme = somme + k
}
La somme des entiers de 1 à 100 vaut #somme.

soit produit = 1
pour k de 1 à 5 {
	soit produit = produit * k
}
La factorielle de 5 vaut #produit.

<h1>Compter sous condition

L'accumulateur placé à l'intérieur d'un `si` ne s'incrémente que sur les tours retenus — le compteur de l'algorithmique classique.

soit diviseurs = 0
pour d de 1 à 84 {
	si 84 % d vaut 0 {
		soit diviseurs = diviseurs + 1
	}
}
84 possède #diviseurs diviseurs.

soit diviseurs = 0
pour d de 1 à 83 {
	si 83 % d vaut 0 {
		soit diviseurs = diviseurs + 1
	}
}
83 en possède #diviseurs : c'est donc un nombre premier.

<h1>Les boucles conditionnelles

`pour` répète un nombre de fois connu d'avance. Quand ce nombre dépend du calcul lui-même, c'est `tant que` qui convient : la condition est vérifiée <gras>{avant} chaque passage, si bien que la boucle peut n'en faire aucun.

soit p = 1
soit rang = 0
tant que p < 1000 faire {
	soit p = p * 2
	soit rang = rang + 1
}
La première puissance de 2 supérieure à 1000 est #p, atteinte au rang #rang.

La variante `faire … tant que` vérifie la condition <gras>{après} chaque passage : le corps s'exécute donc au moins une fois, même lorsque la condition est fausse dès le départ.

soit n = 10
faire {
	Passage unique, avec n valant #n.
	soit n = n + 1
} tant que n < 3

Les deux formes reposent sur l'accumulateur de la section précédente : sans une variable qui avance d'un tour à l'autre, une boucle conditionnelle ne s'arrêterait jamais.

<h1>Interrompre une répétition

Deux mots gouvernent le cours d'une boucle. `sortir` l'arrête entièrement — c'est la recherche qui cesse dès qu'elle a trouvé. `continuer` n'arrête que le tour en cours.

soit premier_diviseur = 0
pour d de 2 à 100 {
	si reste de 91 par d vaut 0 {
		soit premier_diviseur = d
		sortir
	}
}

Le plus petit diviseur de 91 autre que 1 est #premier_diviseur.

pour k de 1 à 6 {
	si reste de k par 2 vaut 0 {
		continuer
	}
	[#k]
}

Seuls les rangs impairs ont laissé une trace.

<h1>Une entrée

Une saisie <gras>arrête le document jusqu'à ce que la réponse arrive : tout ce qui la suit attend. C'est pourquoi elle se place en fin de document, ou dans un document qui ne sert qu'à cela.

`<Saisis>` est la question que le document pose à son lecteur — l'équivalent d'un `input`. La réponse se relit ensuite comme n'importe quelle variable, calculs compris.

soit âge = <Saisis>un entier{Quel est ton âge ?}
soit tarif = si âge moins de 18 { 5 } sinon { 9 }
Entrée : #tarif euros.
